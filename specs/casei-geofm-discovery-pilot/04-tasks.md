# Tasks: CASEI-to-Prithvi-EO Labeled Data Discovery Pilot

Execution context for a fresh session: this repo (`Projects/casei-ai-usecases/`) is greenfield. The governing artifacts are `specs/casei-geofm-discovery-pilot/01-spec.md` (approved), `02-acceptance-criteria.md` (approved), and `03-plan.md` (approved) — read them before starting; they define every schema, taxonomy, and guardrail referenced below. Facts verified live on 2026-09-23: the CASEI API serves full-table JSON at `https://admg.nasa-impact.net/api/<table>` in an `{success, message, data}` envelope with no auth/pagination; `deployment.spatial_bounds` is EWKT (`SRID=4326;POLYGON (...)`); every `doi` record has a CMR `concept_id`; NASA CMR granule search (`https://cmr.earthdata.nasa.gov/search/granules.json`) accepts `short_name`, `bounding_box`, `temporal`, `page_size` and returns `time_start` and `cloud_cover`. Work through tasks in order; run `uv run pytest` after every task and keep it green.

## Task 3: Pydantic schemas
- Files: `casei_geofm/schemas/model.py`, `casei_geofm/schemas/candidate.py`, `casei_geofm/schemas/llm_io.py`, `tests/test_schemas.py`
- Change: `model.py`: ModelCard loading `model_card.yaml`. `candidate.py`: `Candidate` with the field groups from `01-spec.md` §Output — CASEI (campaign, campaign_id, product, product_id, doi, platform, instrument), LABEL (target_variable, label_description, label_type, label_provenance, geometry, spatial_resolution, temporal_resolution), USE_CASE (phenomenon, proposed_task, task_description, potential_science_question), MODEL (model_name, model_version), SATELLITE (per-mission overlap, scene_count, temporal_offset), COMPATIBILITY (science_fit, spatial_fit, temporal_fit, spectral_fit, geometric_fit, label_fit, overall_compatibility, native_or_transformable), TRANSFORMATION (required_steps, estimated_complexity, scientific_validity), RANKING (label_value, prithvi_readiness, novelty, overall_priority), EVIDENCE (evidence_level 1|2|3, metadata_evidence, reasoning, assumptions, uncertainties, urls). String fields default to the literal `"UNKNOWN"`; enums for provenance (`DIRECT_LABEL/DERIVED_LABEL/WEAK_OR_PROXY_LABEL/MULTIMODAL_PAIR/NO_OBVIOUS_LABEL`), compatibility (`NATIVE/TRANSFORMABLE/INCOMPATIBLE`), ratings (`HIGH/MEDIUM/LOW/UNKNOWN`); no numeric score field anywhere; `candidate_id` = sha256 hash (first 16 hex chars) of the tuple (campaign_id, product_id, target_variable, proposed_task, satellite). `llm_io.py`: per-stage request/response models plus a validator helper `reject_unknown_overrides(input_record, response)` that raises if a response supplies a non-`UNKNOWN` value for a field the input marked `UNKNOWN`.
- Done when: `tests/test_schemas.py` passes — candidate_id is deterministic and changes with any tuple element; defaults are `UNKNOWN`; `reject_unknown_overrides` raises on an invented value and accepts an honest response.
